# M2 正式路线

M2 的目标是完成一个本地、可持续的行测学习闭环，而不是把产品做成学习管理软件：学习软件不是学习管理软件；打开就是学习。

本路线保留 M0.x 与 M1 的历史事实。当前开发阶段为 `M2.6`。

## M2.1 数据地基 — 完成

建立个人学习数据的可靠基础：多学习档案、Attempt、Session、LearningState、错题手动移出记录，以及可审计的 Session invalidation。内容题库和私人学习数据继续物理分离，学习记录只引用稳定的 `questionExternalId`。

## M2.2 学习引擎 — 完成

完成普通训练、专项训练、续练、作答与未作答前进的严格区分、答案/解析反馈和训练完成页。M2.2-C3 还完成了错题回顾、错题管理、基础学习状态和训练历史闭环：错题回顾不创建 Session，产生 `wrongReview` Attempt；正确移出错题本，错误保留；缺失公共题安全跳过。

## M2.3 学习状态 — 规划保留，核心已提前实现

核心事实统计已在 M2.2-C3 提前实现：7D/ALL、有效 Attempt/Session 口径、作答数、正确率、累计作答用时、当前错题，以及错题回顾/错题本/当前学习入口。

后续只在需要时完善学习状态的呈现，不重复建设同一套统计或引入诊断、推荐、掌握度判断。

## M2.4 历史与专项 — 规划保留，核心已提前实现

专项训练已可用；训练历史以每个 Session 为一张记录，区分进行中、已完成、提前结束和已撤销。撤销是可审计 invalidation，不物理删除 Attempts；撤销后的统计和 LearningState 会按有效记录重算，并继续尊重历史手动移出错题操作。

后续只补充确有必要的历史与专项体验，不重复实现已有核心能力。

## M2.5 数据仪表盘 / 学习状态 — 完成

学习状态作为学习之下的二级页面，已整合 7D/ALL、正确率、作答数、平均作答用时和克制的学习趋势；时间范围只影响统计数据。它还提供当前训练继续入口、当前错题与错题回顾入口，以及低干扰的三级管理入口。噜噜仅作为视觉身份保留位置。

## M2.6 UI 整合与硬化 — 进行中，尚未验收

基础设计系统、整体 UI/UX、页面层级、移动端/桌面响应式、状态与异常体验与交互细节已进入实现；当前正在依据 UI Design Guide 完成产品级页面构图重设计。M2.6 不因工程底线或结构测试通过而自动验收，仍不改变 M2 的学习数据与业务语义。

## M2 边界

M2 保持本地学习软件的范围：不做云同步、网络账号、社交、AI 诊断/推荐、掌握度/能力模型、题目版本化或其他 M3/未来内容。M2 不把统计塞回正式答题过程，也不以复杂首页取代“打开就是学习”。
